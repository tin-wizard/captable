# Cap Table Page and Round Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "Work in progress" Cap table page with a real, read-only cap table (who owns what, issued and fully diluted, by class), and add a "Model a round" view that estimates dilution, including SAFE and note conversion and an option pool top-up.

**Architecture:** One pure module (`src/server/captable/proforma.ts`) does all the round maths from plain numbers and is specified by worked examples; two thin tRPC procedures (`captable.table`, `captable.proforma`) read the company's rows through the tenant client and call it; the page composes the analytics UI kit already in the repo. No schema change, no new dependency.

**Tech Stack:** Next.js 16, Prisma 5.14, tRPC v10, Tremor v3 (BarChart, DonutChart), `@tanstack/react-table`, vitest, Biome 1.7.3, pnpm.

**Spec:** Chat decisions of 2026-10-13: best-practice scope = read-only cap table plus a "model a round" view; the exit waterfall is deferred. Research (Carta deal pro forma and scenario modeling; SAFE conversion explainers): always show issued and fully diluted side by side; show SAFEs and notes as-if-converted; each SAFE's cap, discount and type drive conversion; the pool top-up is pre- or post-money; pro forma output is an estimate to be cross-checked in a spreadsheet.

## Assumptions (stated so they can be corrected before building)
1. **Holdings** are `ACTIVE` shares and `ACTIVE` options only (same rule as the Overview).
2. **Fully diluted (FD)** = issued shares + active options + unallocated plan reserve (reserve minus active options of that plan, never below 0). SAFEs and notes are *not* in FD until they convert in a modelled round; the table shows their capital in a separate column.
3. **Round model:** one priced round. `preMoney` is the *fully diluted pre-money valuation including converting SAFEs/notes and the pool top-up* (the common term-sheet convention). `newMoney` is cash in. `poolTargetPct` is the *post-money unallocated pool as a share of post-money FD* (0 = no top-up).
4. **SAFE conversion price** = the lowest of: the cap price, the discount price (`roundPrice × (1 − discount)`), and the round price. Post-money SAFE: cap price = `cap / companyCapitalization`, where capitalization = pre-round FD + all converting securities (the YC definition, excluding the new pool top-up). Pre-money SAFE and notes: cap price = `cap / preRoundFD`.
5. **Notes:** principal plus simple interest from `issueDate` to the model date at `interestRate` per year (no compounding, no maturity logic). Missing rate = principal only.
6. **Output is an estimate**: the page labels it "Estimate, not legal advice. Check against your counsel's model."

## Global Constraints
- `securities:read` is required for everything on the page and for both procedures; without it the page shows the existing unauthorized state and the procedures refuse.
- The pure module takes plain numbers only (no Prisma, no dates except note interest which takes `years`), is deterministic, and never mutates the caller's data.
- All maths in `Number`; share counts are rounded to whole shares only for display and CSV, never inside the solver. Solver: fixed-point iteration, tolerance `1e-9` relative on price, max 200 iterations; non-convergence returns `converged: false` and the UI shows "Could not solve with these inputs".
- No schema change in this plan. No raw SQL.
- `pnpm biome check <files>`, `pnpm tsc --noEmit`, full vitest green; one vitest process; never bare `git stash`. Production deploy (image only) by the orchestrator with approval.

## Review Focus
1. **The maths is the product.** Each worked example in Task 1 is a test; the reviewer recomputes at least B, C and D by hand.
2. **Convertibles above the round price.** A SAFE with a huge cap must convert at the round price, never above it. Pinned in Task 1 (example E).
3. **Empty company.** No shares: the table renders a clear empty state and the model refuses with "Add shares first" (division by zero guarded). Pinned in Tasks 1, 2.
4. **Permissions.** A role without `securities:read` gets nothing from either procedure. Pinned in Task 2.
5. **Cross-tenant.** Another company's rows never appear in the table or the model. Pinned in Task 2.
6. **Big numbers.** 10^9 shares and valuations of 10^10 do not lose precision visibly in the table (display rounding only). Pinned in Task 1.

### Task 1: The pure pro forma module

**Files:**

- Test: `src/server/captable/proforma.test.ts`

**Interfaces:**

```ts
export type Convertible = {
  id: string;
  holder: string;
  kind: "SAFE" | "NOTE";
  type: "POST_MONEY" | "PRE_MONEY";     // notes are always treated as PRE_MONEY
  capital: number;                      // principal
  interest?: number;                    // accrued interest already computed by the caller (notes)
  cap: number | null;                   // valuation cap
  discount: number | null;              // 0.2 = 20 %
};

export type RoundInput = {
  preRoundFD: number;                   // issued + active options + unallocated reserve
  existingUnallocatedPool: number;      // part of preRoundFD that is unallocated reserve
  preMoney: number;
  newMoney: number;
  poolTargetPct: number;                // 0..0.5, post-money unallocated pool / post FD
  convertibles: Convertible[];
};

export type RoundResult = {
  converged: boolean;
  price: number;                        // price per share of the round
  postMoney: number;
  postFD: number;
  newInvestorShares: number;
  poolTopUpShares: number;
  conversions: { id: string; holder: string; amount: number; price: number; shares: number; pctPost: number; bound: "cap" | "discount" | "round" }[];
  existing: { shares: number; pctBefore: number; pctAfter: number };
  newInvestorPct: number;
};

export function modelRound(input: RoundInput): RoundResult;
```

Algorithm (write as the function's header comment): iterate on price `P` from `P0 = preMoney / preRoundFD`. Each pass: for each convertible, `A = capital + interest`; `discountPrice = P × (1 − d)` (if d); `capPrice` = `cap / (preRoundFD + Σ conversion shares)` for POST_MONEY SAFEs (use the previous pass's sum, the loop converges), `cap / preRoundFD` for PRE_MONEY/NOTE; `price_i = min(capPrice, discountPrice, P)`; `shares_i = A / price_i`. Then `Σconv`; with `F = postFD`: if `poolTargetPct > 0`, `F = (preRoundFD + Σconv − U + newMoney / P) / (1 − t)` and `T = t·F − U`; if `T < 0` then `T = 0` and `F = preRoundFD + Σconv + newMoney / P`. New price `P' = preMoney / (preRoundFD + Σconv + T)`. Stop when `|P' − P| / P < 1e-9`.

input: { classId?: string; holderType?: "INDIVIDUAL" | "INSTITUTION"; search?: string; cursor?: string; limit?: number /* 1..50 */ }
output: {
  classes: { id: string; name: string }[];
  rows: { stakeholderId: string; name: string; email: string; byClass: Record<string, number>; options: number;
          issued: number; fullyDiluted: number; pctIssued: number; pctFullyDiluted: number; convertibleCapital: number }[];

input: { preMoney: number (>0); newMoney: number (>=0); poolTargetPct: number (0..0.5); asOf?: string /* YYYY-MM-DD, default today */ }

`table.ts` builds rows from ACTIVE shares and options grouped by stakeholder (tenant client, `groupBy`), pool and totals as in `getHoldings`; convertibles are ACTIVE SAFEs and notes (capital, cap, discount, type, interest rate). `proforma` converts each note's interest as `capital × rate × years(issueDate → asOf)` (simple, floor at 0) and calls `modelRound`; holder rows are existing holders (sharesAfter = sharesBefore), the pool (before: unallocated pool, after: pool + top-up), converting holders and "New investors".
